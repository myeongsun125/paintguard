# 작업 범위 및 수정 규칙

이 프로젝트의 현재 재구축 작업은 **`/home/ubuntu/mes-edge-dashboard/` 내부 파일만 수정 대상**으로 삼으며, 외부 업로드 원본은 분석 참조용으로만 사용합니다. 실제 구현 변경은 `client/src/`, `server/`, `drizzle/`, 프로젝트 루트의 문서와 테스트 파일 범위에서만 수행합니다.

| 구분 | 경로 | 규칙 |
| --- | --- | --- |
| 프론트엔드 구현 | `client/src/**` | 공정·품질 화면, 레이아웃, 유틸리티, 스타일 수정 가능 |
| 서버 구현 | `server/**` | 샘플 데이터 로딩, 분석 절차, 테스트 파일 수정 가능 |
| 데이터 스키마 | `drizzle/**` | 실제 스키마 변경이 필요한 경우에만 수정 |
| 프로젝트 문서 | 루트 `*.md` | 분석 보고서, 작업 규칙, 데이터 관계 문서 관리 |
| 외부 업로드 원본 | `/home/ubuntu/upload/**` | **읽기 전용 참조 자료**로만 사용, 직접 수정 금지 |
| 정적 리소스 | `/home/ubuntu/webdev-static-assets/` | 필요 시 외부 업로드 후 CDN URL로 참조 |

현재 대시보드 개편에서는 다음 원칙을 적용합니다.

첫째, **공정 탭과 품질 탭만 실구현**하며 주문량·예지보전·생산량 레이어는 Coming Soon 상태를 유지합니다. 둘째, 데이터 구조는 PaintGuard 분석 결과를 우선 반영하되, 검증 가능한 경우에만 업로드 CSV를 런타임 소스로 사용합니다. 셋째, 테스트 대상은 회귀 위험이 있는 집계 로직과 서버 절차를 우선하며, 화면 전반의 시각적 변화는 프리뷰와 상태 점검으로 함께 검증합니다.

추가 요청이 들어오면 먼저 이 범위 문서를 기준으로 수정 가능 경로를 판단하고, todo.md에 항목을 추가한 뒤 구현을 진행합니다.

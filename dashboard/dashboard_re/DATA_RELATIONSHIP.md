# MES 데이터 파일 관계 정리

이 문서는 사용자가 첨부한 기존 스트림릿 프로젝트와 현재 웹 대시보드 재구축 버전 사이의 **데이터 파일 할당 관계**를 검증 가능하게 남기기 위한 기록이다. 본 프로젝트의 공정 탭은 기존 집계 CSV의 구조를 참고하되, 화면과 상호작용은 새로 재작성하는 방향으로 구성했다.

## 1. 기존 첨부 자료에서 확인한 핵심 관계

기존 압축본을 검토한 결과, 공정 탭과 품질 탭은 서로 다른 성격의 데이터 계층을 사용하고 있었다. 공정 탭은 **집계형 정형 데이터**를 중심으로 KPI와 시계열을 구성하고, 품질 탭은 **개별 결함 단위의 상세 데이터와 이미지 분석 흐름**을 중심으로 설계되어 있었다.

| 구분 | 역할 | 현재 웹 대시보드에서의 반영 방식 |
|---|---|---|
| `inspection_master` 계열 | 검사 개별 건 단위의 원천 로그. 검사 시각, 공장, 라인, 교대조, 판정 결과, 환경값 등이 포함됨 | 공정 탭의 교대조×시간대 히트맵, 온도·습도 상관분석에 사용 |
| `daily_summary` 계열 | 일자·공장·라인·교대조 수준으로 집계된 요약 데이터. 총 검사수, PASS/FAIL, 수율, 평균 택트타임, 평균 추론시간 등을 포함 | 공정 탭 KPI 카드, 수율 시계열, 공장별 불량률 비교에 사용 |
| `defect_detail` 또는 품질 상세 계열 | 결함 유형, 심각도, zone, 모델, 재작업 시간 등 품질 해석용 상세 데이터 | 품질 탭의 Top N, 심각도 분포, zone heatmap, 모델 비교에 사용 |
| 이미지 기반 분석 결과 | 이미지별 결함 위치와 상세 설명을 담는 결과 데이터 | 품질 탭의 업로드 분석, BBox 오버레이, 상세 패널에 사용 |

## 2. 공정 탭에서의 파일 할당 원칙

공정 탭은 기존 구조를 그대로 복제하지 않고, **정형 데이터만으로 시간 흐름을 읽게 만드는 신규 레이어**로 재설계했다. 이때 파일 간 역할은 다음과 같이 분리된다.

| 입력 파일 | 기대 컬럼 축 | 실제 사용 영역 |
|---|---|---|
| `daily_summary.csv` | `date`, `plant_code`, `line_code`, `shift`, `total_inspections`, `pass_count`, `fail_count`, `avg_takt_time`, `avg_inference_time` | KPI 카드, 수율 추이, 공장 비교, 필터 옵션 |
| `inspection_master.csv` | `inspection_datetime`, `plant_code`, `line_code`, `shift`, `result`, `ambient_temp_c`, `humidity_pct` | 시간대 히트맵, 환경 상관 산점도 |

현재 구현에서의 해석 원칙은 다음과 같다.

> `daily_summary.csv`는 **집계 기반 의사결정 계층**, `inspection_master.csv`는 **원천 이벤트 기반 패턴 탐지 계층**으로 분리해서 사용한다.

이 구조 덕분에 사용자는 요약 KPI와 미시적 이상 패턴을 같은 화면에서 연결해 볼 수 있다. 또한 `inspection_master.csv`가 없어도 `daily_summary.csv`만으로 주요 KPI와 시계열은 동작하고, 부족한 고급 시각화는 샘플 집계로 보완된다.

## 3. 품질 탭에서의 파일 할당 원칙

품질 탭은 기존 폼 중심 흐름을 유지하되, 이미지 업로드와 카드 기반 드릴다운을 강화하는 방향으로 재구성했다.

| 입력 파일 또는 입력 방식 | 역할 | 현재 반영 방식 |
|---|---|---|
| `defect_detail.csv` | 결함 유형, zone, severity, model, 재작업 시간 등 품질 상세 집계용 원천 | Top N 바 차트, 심각도 분포, zone heatmap, 모델별 비교 |
| 이미지 업로드 | 단일 이미지 기반 결함 후보 분석 | 서버 분석 절차 호출 후 BBox 오버레이와 상세 패널 생성 |
| 샘플 품질 데이터 | 업로드 전 기본 UX 검증용 | 초기 카드 그리드와 차트 기본값 제공 |

## 4. 현재 프로젝트 내부 반영 위치

현재 웹 프로젝트에서는 데이터 파일과 로직을 다음 위치에 배치했다.

| 위치 | 내용 |
|---|---|
| `server/data/mes/sampleData.json` | 공정·품질 탭의 내장 샘플 데이터 |
| `server/mes.ts` | 샘플 데이터 로드, 이미지 분석, 리스크 등급 계산 |
| `client/src/lib/mes-utils.ts` | CSV 파싱, 공정 집계, 품질 업로드 집계 |
| `client/src/pages/ProcessPage.tsx` | 공정 탭 신규 구현 UI |
| `client/src/pages/QualityPage.tsx` | 품질 탭 고도화 UI |

## 5. 구현상 판단 요약

이번 재구축에서는 공정 탭을 **기존 화면 개선**이 아니라 **데이터 관계만 재사용한 신규 구현**으로 처리했다. 반면 품질 탭은 기존의 상세 폼 성격을 유지하면서도, 이미지 업로드와 리스크 카드 중심 드릴다운을 추가해 고도화하는 전략을 취했다.

이 판단은 다음과 같은 이유에서 타당하다.

| 판단 항목 | 적용 이유 |
|---|---|
| 공정 탭 신규 작성 | 기존 스트림릿 화면은 일반적인 대시보드 구성에 머무르는 경향이 있어, 시간 흐름 중심의 산업 관제 UI로 재설계하는 편이 적합했음 |
| 품질 탭 구조 일부 유지 | 사용자가 기존 form 유지 의도를 명확히 제시했고, 이미지-상세정보 연결 흐름이 기존 자산의 강점이었음 |
| 샘플 + 업로드 병행 구조 | 초기 검증성과 실제 데이터 전환 가능성을 동시에 확보하기 위함 |
